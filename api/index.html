Overview

AccessBay REST API v1

Section titled “AccessBay REST API v1”

Every response, errors and OPTIONS included, sends Cache-Control: no-store, private and Vary: Cookie, and no Access-Control-* header: no caller is a cross-origin browser. JSONP is off (?_jsonp= answers 400 rest_callback_disabled). A path that exists but does not declare the method answers 405 accessbay_method_not_allowed with Allow; HEAD is allowed where a GET is declared, except on a machine-issued GET. Method overrides (?_method=, X-HTTP-Method-Override) and response envelopes (?_envelope=) answer 400. A credential-named query parameter (key, license_key, token, api_key) answers 400 except on a machine-issued GET. Batch requests (/batch/v1) are refused. Errors use the WordPress shape {code, message, data: {status}}, with AccessBay codes (AccessBayErrorCode) or core codes such as rest_invalid_param (schema validation runs before authorisation), rest_no_route and rest_cookie_invalid_nonce.

Information

  • OpenAPI version: 3.1.0

Authentication

Section titled “Authentication”

wpCookieNonce

Section titled “wpCookieNonce”

The WordPress login cookie plus the wp_rest nonce in this header, on every method. Without the nonce core treats the cookie request as anonymous (401 accessbay_unauthenticated); _wpnonce in the query is not accepted (403 accessbay_invalid_nonce); Application Passwords are refused (403 accessbay_application_password_refused); a user without the route capability gets 403 accessbay_forbidden.

Security scheme type: apiKey

Header parameter name: X-WP-Nonce

accessbayActivation

Section titled “accessbayActivation”

A credential carried in the X-AccessBay-Activation header, never in the URL. One that is missing or not accepted is refused with the operation’s own error, whose code is on that operation’s 4xx responses; too many attempts get 429 accessbay_rate_limited.

Security scheme type: apiKey

Header parameter name: X-AccessBay-Activation
